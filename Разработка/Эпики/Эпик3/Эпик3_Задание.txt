# 🎯 Задание на разработку: EPIC3-STAGE1 Настройка Celery и broker

## Контекст
Этап 1 формирует инфраструктурный контур воркера: broker, регистрация задач,
базовые настройки сериализации и очередей.

## Текущее состояние
**Файл:** `project/services/bot_service/app/infra/celery_app.py`  
**Функция/класс:** `celery_app`  
**Текущий вывод/поведение:** Celery-контур может быть неполно настроен  
**Необходимый вывод/поведение:** worker стабильно стартует и видит `llm_request`

## Требования ТЗ
RabbitMQ используется как broker; задача LLM выполняется асинхронно через Celery.
Контракт задачи и границы ответственности фиксируются для всех этапов EPIC3:
`llm_request(sub, role, prompt)` и отсутствие прямых вызовов MAX API из worker.

## Задача
Настроить `celery_app` и регистрацию задач для рабочего запуска worker.

## Технические требования
### 1. Изменения в Celery контуре
**Логика работы:**
1. Настроить `broker` из `.env`.
2. Зарегистрировать `app.tasks.llm_tasks`.
3. Зафиксировать формат сериализации `json`.

### 2. Формат вывода
```
worker start -> queue llm -> task llm_request visible
```

**Где:**
- `llm` - целевая очередь по умолчанию.

### 3. Обработка ошибок
```python

Логировать и завершать worker без зависания в неопределенном состоянии.
```

# 🎯 Задание на разработку: EPIC3-STAGE3 Task `llm_request` и публикация в outbox

## Контекст
Этап 3 реализует основной бизнес-поток воркера: LLM -> outbox.

## Текущее состояние
**Файл:** `project/services/bot_service/app/tasks/llm_tasks.py`, `project/services/bot_service/app/models/outbox.py`  
**Функция/класс:** `llm_request`, `OutboxItem`  
**Текущий вывод/поведение:** задача может быть частичной  
**Необходимый вывод/поведение:** задача формирует `OutboxItem` и `RPUSH` в `max:outbox`

## Требования ТЗ
Воркер не знает MAX API; результат передается через Redis outbox.

## Задача
Реализовать и зафиксировать поток `llm_request(sub, role, prompt)`.

## Технические требования
### 1. Изменения в task и модели outbox
**Логика работы:**
1. Получить `task_id` из `self.request.id`.
2. Вызвать OpenRouter client.
3. Найти `max_user_id` через `GET user_chat:{sub}`.
4. Сформировать `OutboxItem` и `RPUSH max:outbox`.

### 2. Формат вывода
```
{
  "max_user_id": "<chat_id>",
  "text": "<llm_response>",
  "task_id": "<celery_task_id>",
  "created_at": <unix_time>
}
```

### 3. Обработка ошибок
```python
# user_chat не найден
Логировать и завершать задачу без исключения.

# Ошибка OpenRouter
Логировать и формировать безопасный fallback text.
```

## Файлы для изменения
- `project/services/bot_service/app/tasks/llm_tasks.py` - task logic.
- `project/services/bot_service/app/models/outbox.py` - outbox schema helpers.
- `project/services/bot_service/app/core/constants.py` - outbox key.
- **Не изменять:** maxapi handlers.

## Пример реализации
```python
На этом этапе код не приводится. Реализация выполняется в отдельной итерации.
```

## Критерии приемки
- [ ] Успешная задача публикует элемент в outbox.
- [ ] `task_id` берется из Celery, не генерируется вручную.
- [ ] Отсутствующий `user_chat` обрабатывается без падения worker.
