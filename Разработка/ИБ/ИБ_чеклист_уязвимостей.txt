--- Секреты и конфигурация ---
[x] JWT_SECRET в auth и bot совпадают, ≥32 символов, не плейсхолдеры из примеров
    Доказательство: валидаторы `jwt_secret` в `auth_service/app/core/config.py` и `bot_service/app/core/config.py` (плейсхолдеры и пустое значение отклоняются).
[!] JWT_SECRET в auth и bot совпадают друг с другом в рантайме
    Доказательство: совпадение не проверяется кодом — только настройка одинакового значения в двух `.env` при деплое.

[x] MAX_BOT_TOKEN и OPENROUTER_API_KEY не в git
    Доказательство: корневой `.gitignore` игнорирует `.env`; секреты не хранятся в отслеживаемых примерах как реальные значения.
[!] Ротация при утечке проработана
    Доказательство: в репозитории нет регламентов/контактов ИБ по ротации (только общие рекомендации README).

[x] Пароли Redis/AMQP в production не default (guest и т.п.) — как эталон infra
    Доказательство: `project/docker-compose.yml`, профиль `prod-broker-tls` (сервисы `redis-tls`, `rabbitmq-tls`) — `requirepass` у Redis, пользователь/пароль RabbitMQ не guest; в `bot_service` при `ENV=prod` URL брокера с `guest:guest` запрещён в `app/core/config.py`.
[!] Пароли в реальной среде заказчика не default
    Доказательство: локальный `docker-compose.yml` и `.env.example` допускают guest для dev — боевые URL должен задать заказчик.

[x] .env и auth.db с локальными данными не попадают в артефакты git
    Доказательство: `.gitignore` — `.env`, `project/services/auth_service/*.db`.
[!] .env и БД не попадают в публичные образы CI/CD
    Доказательство: нет автоматической проверки в репозитории, что Dockerfile/CI не копируют секреты — ревью пайплайна у заказчика.

--- Сеть и инфраструктура ---
[x] Redis и RabbitMQ недоступны из интернета — в эталонном prod-compose
    Доказательство: `project/docker-compose.yml`, профиль `prod-broker-tls` — сервисы только в сети `backend`, секции `ports` у TLS-брокеров отсутствуют.
[!] Redis и RabbitMQ в интернет не выставлены на стороне заказчика
    Доказательство: фактическая VPC/SG/маршрутизация не контролируется репозиторием.

[x] На хосте не торчат 6379/5672/15672 наружу — по умолчанию в dev-compose
    Доказательство: `project/docker-compose.yml` без `ports` у redis/rabbitmq; опционально локально — `Разработка/ИБ/docker-compose.dev-host-ports.yml` (README шаг 3).

[x] TLS для Redis/AMQP включён там, где требует политика — в коде prod бота
    Доказательство: при `ENV=prod|production` обязательны `rediss://` и `amqps://` (`bot_service/app/core/config.py`); пример TLS-узла — `project/docker-compose.yml` (профиль `prod-broker-tls`), скрипт `project/scripts/gen_sample_tls_certs.py`, `make tls-certs`.

[x] Reverse proxy: лимит размера тела — в приложениях
    Доказательство: middleware по `Content-Length` в `auth_service/app/main.py`, `bot_service/app/main.py`; README рекомендует дублировать на nginx.
[!] Таймауты и WAF на edge
    Доказательство: не закреплены в коде — зона настройки заказчика.

--- Auth Service ---
[x] Rate limit на POST /auth/login адекватен (IP / доверенный прокси)
    Доказательство: `5/minute` в `auth_service/app/api/routes_auth.py`; ключ `rate_limit_key` в `auth_service/app/core/rate_limiter.py` с учётом `TRUSTED_PROXY_HEADERS`.

[x] Rate limit на POST /auth/register включён
    Доказательство: `10/hour` на `/auth/register` (`routes_auth.py`); `GET /auth/me` — `60/minute`.

[x] Политика паролей соответствует требованиям (длина, сложность)
    Доказательство: `RegisterRequest` в `auth_service/app/schemas/auth.py` — min 8, верх/низ регистр, цифра, спецсимвол.

[x] Ошибки логина/регистрации не дают лишней информации злоумышленнику (по политике)
    Доказательство: логин — общее «Неверные учётные данные» (`app/core/exceptions.py`); 409 при дубликате email согласовано с `ИБ_политика_email_при_регистрации.txt`.

[x] /docs и OpenAPI отключены или защищены в production
    Доказательство: `create_app()` в `auth_service/app/main.py` — при prod `docs_url`/`openapi_url` = None.

[x] Security headers применяются (как минимум на auth); HSTS при HTTPS
    Доказательство: middleware в `auth_service/app/main.py` — nosniff, frame deny, HSTS при prod.

--- Bot Service и webhook ---
[x] Подлинность входящих webhook MAX подтверждена по документации (подпись/секрет/IP)
    Доказательство: опционально `WEBHOOK_REQUEST_SECRET`, CIDR, заголовок — `bot_service/app/security/webhook_gate.py`, подключение в `main.py`; модель доверия — `ИБ_webhook_MAX_доверие.txt`.

[x] Security headers на FastAPI webhook при необходимости выровнены с auth
    Доказательство: тот же набор заголовков в `bot_service/app/main.py`, что и у auth.

[x] JWT в чате: пользователи осведомлены о риске копирования токена в мессенджер
    Доказательство: README описывает передачу JWT через `/token` в MAX и сценарий проверки; полный юридический/UX-бриф — вне репозитория.

--- Redis / Celery / Outbox ---
[x] Нет анонимной записи в Redis извне; ACL/пароль — в эталоне и опционально в глубину
    Доказательство: prod-пример с `--requirepass`; опционально `REDIS_INTEGRITY_SECRET` — HMAC ключей/очереди в `bot_service/app/security/redis_integrity.py`.

[x] Очередь Celery защищена; нельзя опубликовать задачу без авторизации брокера — в prod по схеме URL
    Доказательство: в prod требуется `amqps://` с учётными данными не guest; реальная защита брокера — пароль/TLS на стороне RabbitMQ (compose prod example).

[x] max:outbox: риск подделки сообщений оценён; длина text ограничена
    Доказательство: `OUTBOX_TEXT_MAX_LEN`, усечение в `llm_tasks.py`; при заданном `REDIS_INTEGRITY_SECRET` проверка MAC в `outbox_consumer.py`.
